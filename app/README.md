# `:app` module

The only module. It contains the whole app: UI, image processing, storage and export. Everything is in `src/main/java/com/example/cubecut/`, one flat package ([ADR-0003](../docs/adr/0003-single-module-plain-compose-state.md)). To find a file by task, see [ARCHITECTURE § Where to look](../ARCHITECTURE.md#where-to-look-for-x). For the rules that span files, see [ARCHITECTURE § Invariants](../ARCHITECTURE.md#invariants-break-these-and-something-breaks).

**Dependencies:** Compose BOM + Material3, activity-compose, core-ktx, lifecycle-runtime-ktx, Media3 ExoPlayer/UI. No OpenCV since 4.0-0: the readers are plain Kotlin. See [build.gradle.kts](build.gradle.kts).

### Vision
The timer is found and read in plain Kotlin (4.0-0 removed OpenCV, `TimerReader.kt`, `DisplayReaders.kt`, `SolveAnalyzer.kt` and `TimerSetupScreen.kt`: the setup by hand). **Owner rule: don't change the readers or the scans unless asked.**

| File | Responsibility | Main entry points | Gotchas |
|---|---|---|---|
| `SolidDigits.kt` | (3.3-C) Reads times in solid digits (csTimer, phone apps) anywhere in a picture. **No Android** | `findTimeRows`, `pickRow`, `DigitShapes.from` / `learned`, `readDigitStyles`, `GrayPic` | Needs exactly one decimal point; one colon before it is read (`1:04.42`), hours aren't. A digit drawn in two pieces next to a row makes it unreadable (`hasDigitInPieces`): that reader would drop it. The examples come from `assets/digit_shapes.bin` ([ADR-0016](../docs/adr/0016-find-the-timer-without-ml.md)) |
| `TimerFinder.kt` | (3.3-C) Finds the timer by itself and learns its digits. **No Android** | `findTimer(PicAt, duration, fonts, …, otherKind)` → `FinderResult`, `FoundTimer.read` | `otherKind` is asked early when nothing runs (seven-segment). Throws `ScanCancelled`. Reads pictures out of order: give it one frame source of its own |
| `HeldFinder.kt` | (3.3-C) Finds a timer without running decimals by its final times. Pure | `findHeldTimer`, `heldPlace`, `sightingsOf` | Called by `TimerFinder` with the numbers its search saw (`heldPlace`, the grouping, also by `findHeldSegments`); the result has `FoundTimer.held` = read it with `readHeld`, scan it with `scanHeldTimer` |
| `HeldScan.kt` | (3.3-C) Finds that timer's solves. Pure | `scanHeldTimer(read, duration, frameSec, …)`, `SOON_NOTE` | Every text with decimals is a final time: never give it a timer that runs with decimals |
| `FinderScan.kt` | (3.3-C) Finds the solves of a timer `TimerFinder` found. Pure | `scanFoundTimer(read, duration, decimals…, frameSec, frameTime, …, tenths)` → `ScanResult`; also `FoundSolve`, `ScanResult`, `ScanCancelled`, `LEFTOVER_NOTE_START`, `formatDigits`, `CLOCK_NOTE`, `HIDDEN_STOP_NOTE` | `read` gives text with its decimal point (`12.69`), not digits. `tenths` is for displays whose last digits blur while running. The scan's steps are at the top of the file (they came from the removed `SolveAnalyzer`) |
| `SegmentRows.kt` | (3.3-C) Finds rows of seven-segment digits anywhere in a picture. **No Android** | `segmentRows(GrayPic)`, `Bits`, `Flat`, `drawnDigit` | Uses all processor cores. Only a first look: reading is `SegmentGrid` |
| `SegmentGrid.kt` | (3.3-C) The grid of a seven-segment number: reads every digit's place, finds the grid again nearby, makes it fit better. **No Android** | `SegmentGrid.through` / `widenedIn` / `read` / `located` / `refined`, `segmentText`, `tenthsOf` | At most 6 digits, no colon yet |
| `SegmentFinder.kt` | (3.3-C) Finds a seven-segment timer by itself. **No Android** | `findSegments(PicAt, duration, …)` → `SegmentResult`; `findHeldSegments`, `heldSegmentRow` (by final times) | Takes the first number that rises with the clock: ask for solid digits first. `SegmentResult.held` keeps the final times it read on the way, for `findHeldSegments`; use that only when nothing else was found (a QiYi lying on the desk shows final times too). Throws `ScanCancelled` |
| `SegmentTracker.kt` | (3.3-C) Follows a found seven-segment timer through the video, reads it, scans it. **No Android** | `SegmentTracker.follow`, `shown`, `scanSegments` | Keeps only the last reading, because the scan asks for the real time of the frame it just read |
| `MissedSolves.kt` | (3.3-C) Where a solve may be missing. Pure, no screen | `hintsOf(ScanResult)`, `findMissedSolves`, `mergeHints`, `hintsToShow`, `MissedHint`, `HintReason`, `ScanTrace` | `HintReason.key` is stored: never change it. Every scan keeps a trace |
| `MissedHintCard.kt` | (3.3-C) The card of one hint | `MissedHintCard` | Knows nothing about the editor (4.0 shows it in a popup) |
| `AutoScan.kt` | (3.3-C) *Find solves*: the glue between the video and the pure parts, and the *Which one is your timer?* window | `analyzeByItself`, `AutoScanResult`, `NeedsUser`, `TimerQuestionDialog`, `loadDigitFonts`, `frameTimeOf` | Opens its own frame source |
| `FrameSource.kt` | Frames for the scan | `GraySource`, `openFrameSource`, `CodecSource`, `RetrieverSource`, `AutoSource` / `calibrate` | Hands out `GrayPic`s, nothing to release. The grey values must stay as OpenCV made them (`GRAY_R`…, `STRETCH`), or the readers see other pictures. Logs `Frame source:` under tag `CubeCut`. Keep the fallback |

### Resources
- `assets/digit_shapes.bin`: example digits for `SolidDigits.kt`, made by `tools/make_digit_shapes.py`. `assets/digit_fonts_license.txt`: the licences of those fonts; it must stay in the app.
- `res/layout/video_player_view.xml`: the TextureView `PlayerView`, required for editor pinch zoom and for the viewer.
- `res/values(-night)/themes.xml` and `colors.xml`: window background only (`window_background`). The `black` and `white` colours are template leftovers.
- `res/xml/data_extraction_rules.xml`: excludes everything from Google backup and transfer (the app has its own backup file, `Backup.kt`).
- `res/drawable/cubecut_logo.png`: the header logo. `mipmap-*`: the launcher icon.
- `strings.xml` holds only `app_name`. **UI text is written directly in Kotlin** (see [CLAUDE.md conventions](../CLAUDE.md#conventions)).

## Tests

`src/test` holds plain JUnit tests of the pure functions (no Android needed):
- `ComputeClipsTest`: `parseTimeSeconds` and `computeClips`, including per-clip buffers;
- `RescanMergeTest`: `mergeRescan` and `checkCuts`;
- `CutFieldsTest`: *Shared on* storage, toggling and filter, the v7 fill from notes, tag fallback, single-solve clips (`clipsFor`), and restore matching (`matchVideo`, `matchExport`);
- `TagsTest`: tag resolving, labels, filter, selection rules and tagged file names;
- `PenaltyTest`: penalty display, file-name part, renaming an exported name, and that a penalty never moves a clip;
- `GroundTruthTest` (3.3-A): the ground-truth JSON (also old files with a setup by hand), csTimer's CSV, `compareScan`, `compareTimes`, `gradeReading`, the report text, and every file in `src/test/resources/groundtruth/`. `FakeDisplay` is a simulated timer display for it;
- `SolidDigitsTest` (3.3-C): the solid-digit reader on drawn times, always in a font it isn't given;
- `TimerFinderTest` (3.3-C): the finder on a drawn session (`DrawnTime` draws for both tests);
- `SegmentFinderTest` (3.3-C): the seven-segment finder and grid on drawn displays (turned, leaning, small, faint, noisy), following and scanning a display that jumps, a display that shows only its final times, and closing against its definition;
- `MissedSolvesTest` (3.3-C): the hints on a simulated session, and on what the scan saw in the reference videos (`D:\CubeCutRef\traces`, written by `ReferenceVideoTest`; skipped without them): none where nothing is missing, one where a solve is taken out;
- `HeldTimerTest` (3.3-C): finding and scanning a drawn or simulated timer that hides its running time or shows whole seconds;
- `FinderScanTest` (3.3-C): the scan of a found timer on a simulated csTimer (covered timer, hidden stop, misreads, blended frames), and on one whose last digits blur;
- `ReferenceVideoTest` (3.3-C): the app's own finder and scan on the whole reference videos, through ffmpeg. Also small camera moves, and that the seven-segment finder finds the QiYis and nothing in other videos (`findsOnlyTheSevenSegmentTimers`), and scans the QiYis against their `.frames.txt` (`scansTheSevenSegmentTimers`). Only with `CUBECUT_REF_VIDEOS=1` (about 17 minutes), or set to part of the names (`4x4`); not while another Gradle run is busy; add `--rerun-tasks`, or Gradle may skip it as already done. A video needs a `.places.txt` beside it
- `ReferenceFramesTest` (3.3-C): the same on whole frames of the reference videos. Skipped on a computer without `D:\CubeCutRef`;
- `PuzzleIconsTest`: every puzzle logo stays inside its box; NxN has N² stickers.

The tests written before 3.2-A lock the 3.1 behaviour: if one fails, a clip or a merge moved. `src/androidTest` is still the template (`ExampleInstrumentedTest`). `org.json` is a test dependency because `android.jar` only has stubs of it.
